# Manual Windows acceptance scripts

All scripts below are **not run**. These are planned acceptance scripts, not results. Use copies of existing data, disposable Windows accounts/VM snapshots and both C# and Rust release builds. Do not run two tray apps simultaneously except the explicit IPC cross-compatibility scenario. Record date, OS/build, architecture, build SHA, steps, actual result and evidence for each execution.

1. **Migration/rollback.** Prepare copies of installed HKCU EarTrumpet settings, portable config and packaged LocalSettings, including XML hotkeys/numeric values, string booleans, unknown keys and old profile/rule schemas. Hash/export originals. Launch Rust migration. Expected: migrated settings/rules/themes/hidden items/profiles/hotkeys/consent match; originals remain byte/value equivalent; failed/corrupt entries are reported/recoverable without replacing originals. Reopen C# and confirm rollback still works.
2. **CLI wire compatibility.** Start C# tray app and use Rust client, then reverse. Exercise C01–C24, every alias and flags, Unicode/quoted names, unmatched quotes, empty command, relative values, missing apps/devices, no server, bad paths and large responses. Expected: per-command JSON shapes/errors match captures; session-suffixed current-user pipe, UTF-8/LF and CR handling work; watch is a snapshot. Direct exe help/version and bt.cmd output/exit codes match their distinct originals.
3. **Audio devices/sessions.** With two outputs and microphone, play desktop/UWP/browser audio, System Sounds and multiple sessions per app; change endpoint/session volume/mute/channels, route to another device, change console/multimedia/communications defaults, unplug/replug, restart Windows Audio service. Expected: names/icons/groups/peaks/defaults/routing and recovery track C#; stale handles/callbacks do not crash.
4. **Tray/window interaction.** Exercise left/right/middle/keyboard invoke, hover delay, scroll hook, full tray menu, shell restart, taskbar edges/overflow, two monitors and DPI scaling. Expected: correct flyout bounds/focus/dismissal/pinning, per-device app sections and all restored hidden items; keyboard-only operation and screen-reader names available; icon states/animation/badges match preferences.
5. **Hotkeys/undo.** Record every global/per-device/per-profile binding; provoke collision and replace/remove bindings. Hold cycle/preset keys; operate Ctrl+Z/Y/P and Ctrl+click solo. Expected: no firing during recording, original debounce and registration rules; 50-action history with <500ms volume coalescing, mute separation, correct redo clearing and no replay recursion.
6. **Settings/bridge.** Visit every modern/classic settings page; mutate each inventoried key/action; search static/dynamic entries; collapse sidebar; resize/reopen; simulate webview load failure. Expected: state round-trips match original transforms, live updates from CLI/hotkeys/import appear, all buttons including legacy entry work, appropriate confirmation/error/fallback UI appears.
7. **Presets/rules/focus lost.** Import old profiles and rule data; capture current/all devices/apps-only/default slots/no-apps/no-route, edit entries, rename/delete/export/reimport/cycle. Test missing outputs/apps and later appearance, launch/lock/hard mute/folder defaults/pinned neutral entries. Switch foreground with 0/positive attenuation and 0/5000ms fades, selected scope and shutdown. Expected: exact result counts/warnings/summary/roles, target volumes and restoration/precedence match source.
8. **Themes/accessibility.** Compare all twelve palettes/categories, seven channels, opacity, peak styles, import old/custom themes, dynamic album art, light/dark Windows, high contrast, reduced animations and battery/eco. Expected: exact settings values/fallbacks and usable contrast/navigation; no unnecessary background peak/animation work when hidden.
9. **Media.** Test GSMTC and each available legacy player, multiple sources, paused/no media, hover/hide, art cache/expansion, seek/shuffle/repeat/transport and app volume. Expected: source/capabilities/art/timeline and legacy fallback match; unsupported controls are handled; no orphaned callbacks after closure/process exit.
10. **Onboarding/startup/shutdown.** Fresh disposable profile: ordinary launch, second instance, Left Ctrl launch, tray wizard, Back/Next/Skip/close; startup task/Run toggle, logoff and shell restart. Expected: silent normal first launch, five-page manual wizard, correct preferences/consent writes and startup gates; one tray owner, flushed local logs and clean pipe/mutex/media/audio teardown.
11. **Service consent and diagnostics.** Intercept requests locally with test fixtures; exercise telemetry absent/opt-in/opt-out/region defaults, Store identity, updates/channels/checksum failures/installer/portable, feed toggle/unread/poll retry/results. Expected: only original endpoints/fields/gates, no request while disabled, no new collection. Export diagnostics manually and crash in a disposable build. Expected: staged review before manual zip, immediate crash zip, path sanitization and local retention, no automatic diagnostic upload. Never submit synthetic votes to production.
12. **Locales/packaging.** Install x64/arm64 packages in clean Windows environments including requested minimum supported build, test all supplied culture lookup/format placeholders and at least RTL, startup/PATH/uninstall/portable marker/bt.cmd/update flow. Expected: consistent versions/architecture assets/license/credits, translations/culture fallback and script compatibility; originals survive migration/uninstall.
13. **Performance comparison.** On the same machine and identical sessions, measure C# and Rust release binary/install size, full process tree private bytes/working set, idle CPU over a fixed interval, disk bytes/writes, and at least 30 warm tray clicks measured to first visible frame. Test settings/media open and closed separately. Expected: recorded measurements rather than estimates; warm flyout target <150ms with raw samples/distribution, including all WebView2 children in memory totals. If missed, record evidence and alternative proposal before changing UI stack.

14. **Native Windows path resolver.** Compare the Rust app adapter against C# Path.GetFullPath for relative/drive-relative/current-drive-rooted paths, changed working directories, drive-specific context, UNC/device prefixes, dot segments, invalid NUL/unsupported/overlong inputs. Expected: the adapter preserves source results and error categories; portable logical folder matching does not substitute Linux path behavior. Check quoted executable eligibility separately from normalized under-folder matching, and verify original settings are never changed. Captured core fixtures use a deterministic Windows cwd tag; they do not prove the native adapter works.

Expand these scripts with source-specific edge cases during each milestone. Mark results only after actual execution; Linux unit tests cannot satisfy native UI/audio/COM acceptance.

15. **CLI rule native selection/order.** On a disposable Windows audio setup, create sessions for the same app on two outputs. Compare C# and Rust `rule-preview --keep APP=20 --keep DISPLAY_NAME=80 --others mute --current-device`, then `rule-apply` and `resolve-apps`. Include no-ID/blank-ID sessions if a test adapter is needed, mixed-case IDs, null display names and Unicode display names. Expected: first matching group wins, later suppressed queries retain original warnings, preview scope label does not restrict planning to one output, fallback selection ignores device IDs during application, counts and final volumes/mutes match source. Repeat parsing under en-US and at least sv-SE/ar-SA and record numeric sign behavior. Golden snapshot fixtures do not prove native setter or dispatcher behavior; installed culture-adapter acceptance is covered by test 16.

16. **Native current-culture adapter.** In disposable Windows profiles/VMs, compare installed C# and Rust CLI behavior under en-US, sv-SE, fi-FI, ar-SA and fa-IR, including user number-format overrides. Record the actual positive/negative sign strings and compare culture-aware StartsWith for ASCII signs, U+2212, U+061C/U+200E prefixes, leading whitespace and NUL-containing direct pipe inputs. Submit volume values `+10`, `-0`, `−0`, culture-native sign plus digits, and `+2147483647` from an initial volume of 70, plus corresponding rule targets. Expected: original branch, exact error category/message, parsed integer, wrapping/clamping and final volume match; installed commands supply current signs and collation rather than the invariant convenience parser. Repeat on supported Windows versions/architectures. The core's 19-format oracle supplies captured prefix results and therefore does not verify this native adapter. Keep tests local and restore disposable locale settings afterwards.

17. **Preview tray app (D34).** Build `cargo build -p bt-app --release` and run `rust/target/release/BetterTrumpet.exe`. Left-click the tray icon, then click it again; click elsewhere; press Esc. Expected: the flyout opens above the tray, closes on the second click, on focus loss and on Esc, and never reopens from the same click that closed it. Press Ctrl+P: "Pinned" appears and the flyout stays open on focus loss until Ctrl+P again. Leave it open for a minute: its size stays constant (regression for the width-growth crash). Drag the device and app sliders, use the mouse wheel over them, and toggle mute buttons while audio plays in at least two apps and on two devices. Expected: Windows' own volume mixer shows the same values immediately, peaks move with audio, apps appear and disappear as they start and stop audio, a device unplugged or disabled disappears without errors, and the default device carries the Default badge. Right-click menu: Volume mixer and Sound settings open the matching Windows pages; Exit removes the tray icon and ends every WebView2 child process. Expected for the preview: BetterTrumpet's own settings are untouched. Daily-use additions (D46): "Set default" on a device and a device in the tray menu both switch the Windows default output (Sound settings agrees, the tray check mark and tooltip follow within a second); apps show their product names and icons; launching the exe again opens the running flyout instead of a second tray icon; "Start with Windows" survives a sign-out/in and never changes the C# app's own startup setting.

Expected: sorted clones, no-op decisions, raw-store values and observer notifications match C#; migration writes precede mutation writes and do not independently raise AppRulesChanged; the legacy source is untouched. Native sorting and observer delivery remain unrun even though portable lifecycle fixtures pass.

19. **Hidden collection UI and observers.** In disposable C# and Rust profiles with two output devices and multiple app identities, hide an app using both its app ID and executable; query/hide it again with one identity changed. Expected: either identity can match hidden lookup, but removing one saved entry requires its exact tuple; duplicate hides do not rename it. Hide/unhide every app for one device, then all apps, and hide/unhide individual/all devices; repeat no-op operations. Compare displayed counts, per-device/global ordering, observer counts, and state after process restart. Expected: only real changes save/notify, returned settings views cannot mutate cached entries, hidden-app/device stores remain separate, and loaded normalization does not itself save. Repeat culture comparisons from script 18 with blank/accented display names. If using synthetic IDs containing pipes, compare the preserved live-versus-reload delimiter-collision behavior (Q38). Native UI/store/observer delivery remains unrun.

20. **Portable migration deployment and interruption.** Use copies of a portable install on NTFS and exFAT, with C# stopped. Record a source-file hash and retain an external copy. Start the integrated Rust app (once startup wiring is implemented), then restart after changing the legacy copy. Expected: config/rust/migration.v1.json contains the first source bytes; the original stays unchanged by Rust and subsequent launches use the archive. Terminate the process while staging, then relaunch. Expected: a completed archive is never replaced, incomplete staging is not mistaken for it, and the original remains recoverable. Repeat with a read-only destination, corrupt archive and a newer format/version; expect a surfaced local error with no automatic overwrite. Finally test migration while C# is saving settings; startup coordination must produce a stable recoverable snapshot or a clear retry outcome. Record filesystem/OS/build and interruption evidence; temp-directory concurrency tests alone do not prove this deployment behavior.

21. **Installed registry migration across supported Windows targets.** In disposable Win10/Win11 x64 and ARM64 accounts, prepare copies of the EarTrumpet registry key with XML scalars/hotkeys/placements, REG_EXPAND_SZ, native integer/multi-string/binary values, default/unknown addon values and a denied-read key. Record raw value/type/name exports and last-write metadata. Run the integrated registry migration once startup selection is implemented; repeat after modifying or denying access to the original. Expected: first raw archive preserves every value; later runs use the archive without reading/writing the original; a missing key remains missing; denied reads or observed concurrent edits produce a local recoverable error. Exercise a concurrent C# saver and verify stable capture/retry behavior without claiming a transaction. Compare the D42 decoded getters with C# on each target, particularly native casing, environment expansion, lone UTF-16 surrogates and odd-byte strings at 511/513, 1023/1025 and 2047/2049-byte boundaries. The automated x64 fixture tests do not replace this OS/architecture/startup acceptance.
